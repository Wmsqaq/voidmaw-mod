# beta.20 项目审查与验证记录

## 已修复

- 圆盘贴图：真实 beta.19 客户端日志显示 `Missing textures in model voidmaw:item/hole_disc`。原图集声明位于 voidmaw 命名空间，不能扩充 minecraft:blocks。纹理迁入 `textures/item/hole_disc.png`，模型同步引用 `voidmaw:item/hole_disc`，使用原版自动图集目录源。移除错误图集文件。
- 圆盘脚底位置：使用玩家真实 Y，半砖/台阶不再被取整地面高度抬高。跨维度时丢弃旧圆盘并在当前维度重建。圆盘不写入存档；服务器停止清理运行状态。
- 按用户最新要求删除所有 BlockDisplay 方块残影、分步缩小、插值动画。吞噬时直接移除方块，掉落进仓库。
- 吞噬边界：包围盒仅作粗筛，增加圆形半径和脚底平面精筛；方块使用 ceil(脚底高度)，不挖半砖下地形；自然下落方块也受半径、硬度和黑名单约束。
- 生物吞噬：高空生物先向平面下拉，不再只凭水平位置隔空消失；只处理生物、物品、经验，保护其它装饰/显示实体。保留吸收等级规则。搬走村民/悦灵等 InventoryOwner 和马类运输库存，避免 discard 后库存丢失。
- 方块掉落：移除前生成 loot 并传递 BLOCK_ENTITY，保留名称/容器组件。普通容器内容单独入库且清空原库存以避免散落重复；潜影盒内容留在盒子物品组件内。
- 仓库界面：原 slotIndex>=45 误拦截玩家背包，改为仅拦截45..53；导航装饰改为每个视图独立数据，不落盘且不可取出。
- 仓库存档：保存失败保留 dirty 重试，临时文件原子替换；损坏 JSON 不覆盖原文件；缓存按服务器隔离并退出时释放。每两秒保存不再依赖黑洞是否开启。
- 首次礼包：确认背包/落地发放成功后才标记已发放。
- 客户端：隐藏宿主只影响渲染状态，不改实体 invisible flag；退出/换世界清除状态；倒计时按客户端游戏 tick 推进，单人暂停时不继续计时；HUD 边界及配置数值校验。
- 网络：新增版本化 mass_sync_v2，保留读取 beta.18/19 旧载荷的能力；只向支持新频道的客户端发送；仓库按键在游戏内且有频道能力时发送。
- 指令：个人仓库/status 允许普通玩家使用，开关测试和自爆指令仍要求 OP2。
- 部署脚本：先复制并比较新 jar，成功后替换与删除旧版本，避免复制失败先删旧 jar。

## 验证

- `gradlew build` 成功。check 自动执行 Fabric Knot 环境下的两个回归测试，不将测试入口打包到正式 jar。
- AbsorptionRegressionTest：圆形边界、下方实体保护、负高度/半砖方块边界、高空吸引、等级阈值/越界、吞噬延时上限、新旧网络格式 round-trip。
- WarehouseRegressionTest：跨视图导航隔离、导航不可取出、跨页合并、JSON 保存/加载、取出后持久化、损坏文件不覆盖、保存失败后重试。
- 损坏文件和阻塞路径测试主动制造预期 WARN，用于验证错误处理，不是正常游戏报错。
- 最终 beta.20 runServer：到达 Done，指令树注册正常，stop 正常保存全部维度，无异常。
- 修复后的开发客户端实际成功加载 blocks 图集，不再出现 voidmaw 缺失纹理警告；用户实测确认“黑洞视觉效果无问题”。此确认针对圆盘视觉，不代表所有存档、联机或光影组合均已实测。

## 保持的设计与验证范围

- 吸收等级、质量阈值和自爆规则保留；到时安静关闭，只有特殊交互/管理指令引爆。
- 未进行任意第三方模组组合、全部容器自定义掉落表和全部生物装备的穷举测试。自定义实体应遵循原版 InventoryOwner/马类库存接口，未声明的模组私有库存无法通用提取。
- 当前新版客户端能读取旧同步数据；旧客户端连新版服务端不接收新 HUD 频道。联机建议客户端和服务端使用相同版本。
